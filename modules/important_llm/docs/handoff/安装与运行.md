# 安装、配置与运行

## 1. 环境和目录

使用 Python 3.12（已使用 3.12.14 验证）。运行依赖由 `requirements.lock.txt` 锁定，直接依赖声明在 `pyproject.toml`。代码不需要 GPU；GPU/推理资源由外部模型服务提供。本模块只加载 tokenizer，不加载模型权重。安装依赖时需要软件源网络或调用方准备的离线 wheel 仓库。

在解压后的包根目录创建唯一的 `.venv`：

Windows PowerShell：

```powershell
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.lock.txt
.venv/Scripts/python.exe -m pip install --no-deps -e .
$env:BOOK_EXTRACTOR_TOKENIZER_PATH = (Resolve-Path data/tokenizers/qwen3.8-27b).Path
.venv/Scripts/python.exe examples/check_installation.py
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

Linux/macOS shell：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m pip install --no-deps -e .
export BOOK_EXTRACTOR_TOKENIZER_PATH="$PWD/data/tokenizers/qwen3.8-27b"
.venv/bin/python examples/check_installation.py
.venv/bin/python -m unittest discover -s tests -v
```

后文 `python` 指上述虚拟环境中的解释器。离线自检与测试不调用付费服务；不能用它们代替目标服务上的语义验收。测试中平台专属检查可能跳过。项目脚本须在包根目录运行；安装后的 `book-extract` 命令可从其他工作目录调用，但相对路径需由调用方明确。

## 2. 服务配置

将根目录 `llm_services.example.json` 复制为 `.llm_services.json`，不要直接把实际凭据写入示例文件。

```powershell
Copy-Item llm_services.example.json .llm_services.json
$env:LLM_API_KEY = "填写服务凭据"
```

```sh
cp llm_services.example.json .llm_services.json
export LLM_API_KEY='填写服务凭据'
```

| 字段 | 含义与约束 |
|---|---|
| `default` | 默认服务名称；没有默认且配置多服务时必须显式指定 |
| `services.<name>.base_url` | OpenAI 兼容基础 URL，不是 `/chat/completions` 完整路径；缺少独立 `v1` 路径段时补 `/v1` |
| `api_key_env` | 保存密钥的环境变量名称；缺失时报错。无鉴权的内网服务也须提供其接受的非空占位值 |
| `model` | 服务实际接受的模型 ID；可为模型别名或模型路径，按部署填写 |
| `tokenizer_path` | 本地 tokenizer 目录；相对于配置文件解析，未配置则读取环境变量 |
| `mode` | `json`、`json_schema` 或 `tools`；必须与服务实际能力一致，默认 `json` |
| `temperature` | 0–2 的有限数值，默认 0；示例设为 0.7，不保证各模型最佳 |
| `extra_body` | 服务支持的附加参数；示例使用 vLLM 的非思考模板参数。不能覆盖模型、消息、输出结构、temperature 等保留字段 |
| `gateway_retries` | 每次逻辑调用额外允许的 HTTP 504 重试数，默认 10 |

`load_service()` 只读取上表的服务字段。不要把 `context_limit`、`timeout`、`attempts` 或 `max_connections` 填入 JSON 后就认为生效：它们由 CLI 或 Python 构造参数设置。

附带分词文件为 Qwen3.8-27B 的本地文件快照，见[分词器文件说明](分词器文件说明.md)。分块、候选证据预算、综合合批及完整消息计数共用模型原生分词器与聊天模板。缺文件立即失败；不会联网下载或改用近似分词器。切换模型、模板、工具调用格式后，需用服务返回 usage 对照本地输入计数。`input_token_delta` 反映差异；不能通过经验乘数掩盖差异。API 计费用量仍以服务真实 usage 为准。

JSON Schema 只约束结构，不验证名称和释义是否正确。思考开关必须按服务格式设置，并用真实响应核验；仅传入 `enable_thinking` 不能证明服务执行了预期模式。未配置 extra_body 且未显式传思考开关时，不注入任何供应商参数，使用服务自身默认值。api_key_env 只能填写环境变量名；内联密钥如确需使用，应填写 api_key，不能把密钥放入变量名字段。

## 3. CLI 接入

```sh
# 单本
python -m book_extractor.cli --input examples/books/chinese.md --title "滨海拦污设施水动力响应试验研究（节选）" --subject "hydraulic_engineering" --services .llm_services.json --output work/runs --workers 4 --max-connections 4 --transport-failure-limit 2

# 批量；book_id由清单提供
python -m book_extractor.cli --manifest examples/books.json --services .llm_services.json --output work/runs --workers 4 --book-workers 1 --max-connections 4 --transport-failure-limit 2

# 同一输出目录、配置和原文恢复
python -m book_extractor.cli --manifest examples/books.json --services .llm_services.json --output work/runs --workers 4 --max-connections 4 --transport-failure-limit 2 --resume-existing
```

`book-extract` 与 `python -m book_extractor.cli` 等价。常用参数：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--input` / `--manifest` | 必选其一 | 单 MD 或批量 JSON 清单 |
| `--output` | `outputs/extraction` | 运行结果根目录，每本在其中生成 run 子目录 |
| `--services` | `.llm_services.json` | 服务配置文件 |
| `--service` / `--model` | 配置值 | 选择服务、覆盖模型 ID；覆盖模型不自动更换分词器 |
| `--chunk-tokens` | 4000 | MD 块的原生 token 上限；完整请求另做预算检查 |
| `--workers` | 4 | 每书逻辑工作线程上限 |
| `--book-workers` / `--book-prefetch` | 1 / 0 | 基础驻留书数和允许额外预取的书数 |
| `--max-connections` | 100 | 主服务全局 HTTP 在途及连接数上限，不是每书额度 |
| `--max-output-tokens` | 8192 | 模型输出上限；长释义可显式设 16384，同时确认上下文预算 |
| `--timeout` | 180 秒 | HTTP 读写阶段超时，不是任务总时间上限 |
| `--transport-failure-limit` | 未设置 | 单次逻辑调用连接/5xx 失败上限，建议接入先设 2 |
| `--thinking` / `--no-thinking` | 尊重配置 | 显式覆盖相应思考开关，二者互斥 |
| `--resume-existing` | 关闭 | 查找原运行并严格校验后恢复 |
| `--compatible-implementation` | 无 | 经过验证的旧源码指纹白名单；不是绕过模型或输入检查的开关 |

多服务只在需要时启用：`--additional-service <name> --additional-max-connections <n>`，清单每本的 `service` 必须属于显式启用的服务。每本服务固定，额度按服务分别统计。集成初期用单服务即可。

退出码：0 表示本次清单均为 `complete` 或明确 `skipped`；1 表示包含不完整结果或发生运行异常；2 常用于参数错误。**0 不等于所有输入都提取成功**，必须检查 `batch.json` 的逐书状态及覆盖数量。异常退出也可能尚未写完 batch，不能只消费标准输出。

## 4. Python 接入

完整可运行入口见 [examples/run_python.py](../../examples/run_python.py)。核心调用：

```python
from pathlib import Path
from book_extractor.llm import LLMClient, load_service
from book_extractor.pipeline import extract_book

client = LLMClient(
    **load_service(Path(".llm_services.json")),
    max_connections=4,
    max_output_tokens=8192,
    transport_failure_limit=2,
    context_limit=32768,
)
try:
    result = extract_book(
        Path("examples/books/chinese.md"),
        Path("work/runs"),
        client,
        title="滨海拦污设施水动力响应试验研究（节选）",
        subject="hydraulic_engineering",
        book_id="sample-chinese",
        chunk_tokens=4000,
        workers=4,
    )
finally:
    client.close()
```

当前接口是同步阻塞函数，返回 manifest 字典；没有 HTTP 服务、异步任务队列或管线客户端。上游可用子进程调用 CLI，或在工作线程内调用 Python API。不同进程的 HTTP 限额互不共享；集成方还需控制全局进程数。`extract_book()` 不像 CLI 那样根据清单语言自动跳过，Python 调用方负责语言过滤。

`LLMClient` 可额外设置普通调用 `attempts`（默认 3）、`context_limit`（默认 32768）。这些参数须与服务能力对应。需要取消时调用 `client.cancel()`，它对共享该客户端的所有工作生效，不是独立的单书取消；使用结束后总是 `close()`。

## 5. 批次验证与交接

```sh
python scripts/validate_runs.py work/runs
python scripts/summarize_md_runs.py work/runs
```

校验脚本检查来源回拼、引用、成员覆盖及状态一致性，结果写入 `validation.json`；它不是语义验收。统计脚本生成 `statistics.json`，不调用模型。两者只能在本批写入停止后执行，不要对半写入目录宣布验证成功。校验使用断言，运行时不要加 `python -O`。

可选的逐书清洗导出：先使工作目录符合 `work/inputs/manifest.json` 和 `work/runs/<run_id>/...` 布局，再运行 `python scripts/export_cleaning_delivery.py work delivery/batch_name`。正式清单必须包含每本明确的 `book_id`，且每本恰有一个匹配 run，所有书已结束为 complete/partial；输出目录必须不存在。导出仅按流程状态筛选，不改名称释义，不跨书去重。普通上游管线也可直接按契约消费 records，无需使用该文件导出工具。
