# 管线接入契约

## 1. 模块边界

输入：单本原样 UTF-8 MD，以及书籍标识、书名和可选学科。输出：逐书候选、知识点、来源定位、运行状态和统计。只处理中文、英文及中英混合；不接收 PDF、EPUB、上游解析对象、图片内容或跨书证据。调用方负责文本转换质量、书目选择、权限和语言筛查。

建议串联：MD 转换/筛选 → 本模块逐书抽取 → 独立清洗 → 分类挂载 → 跨书去重。抽取中的来源核验、名称判定和定向复核用于保障生成过程，不取代独立清洗。

## 2. 输入清单

见 [examples/books.json](../../examples/books.json)。最外层是 `books` 数组：

| 字段 | 要求 |
|---|---|
| `local_name` | 必填，本机可读 `.md` 路径；相对清单文件目录解析，不相对当前命令目录 |
| `book_id` | 接入建议必填，稳定且全批唯一的书籍 ID；缺省由源文件字节哈希前 16 位生成。用于文件导出时使用安全文件名字符 |
| `title` | 可选，缺省为文件名 stem |
| `subject` | 可选，自由文本学科提示，不是预设分类树 |
| `sha256` | 可选，原文件字节的 64 位小写 SHA256；不匹配会在该书调用模型前拒绝 |
| `language` | 建议显式为 `zh`、`en`、`zh-en`；CLI 跳过其他明确值。缺省不执行自动全书语言识别 |
| `service` | 可选，配置中且在 CLI 已启用的服务名称 |

CLI 校验基础清单格式，不等价于完整的上游业务校验。调用方需排除重复 book_id、重复源路径、无效学科值等。示例清单 Schema 随包给出供上游校验，不会被 CLI 自动加载。

大文件传路径，不在 JSON 中重复携带整书 `text`，也不把整书直接发送 LLM。程序会把整书 MD 读入内存后切块；因此它不是流式文件解析器。单书内容加结构单元、候选、证据等会占用多份内存。超大书或多书并行时需限制驻留书数。原文块上限不等于完整请求长度，提示、Schema、证据和输出预留均另行计量。

## 3. 文件与身份

```text
output/
  batch.json
  <run_id>/
    manifest.json
    source.md
    units.json
    chunks.json
    regions.json
    preprocess_summary.json
    discovery/
    candidates.jsonl
    name_decisions.jsonl
    synthesis/
      verification/
    records.jsonl
    executions/<execution_id>/
      execution.json
      events.jsonl
      summary.json
```

`book_id` 是业务书籍身份；`run_id` 是输入与语义配置的运行身份；`execution_id` 是每次执行/恢复的账本身份；`record_id` 只用于当前运行记录定位。不要把 record_id 当作跨书、跨模型、跨配置的永久概念 ID。

源码指纹、依赖、模型、服务、分词器、提示及语义配置参与运行/缓存身份。新模型不复用旧模型内容缓存。HTTP 连接数等调度配置的改变不等于内容配置改变。交付包重跑形成的新 run 不应与旧生产 run 手工拼接。

## 4. 最终 Record

权威模型为 `src/book_extractor/models.py:Record`；静态字段 Schema 为 `schemas/md-record-v1.schema.json`，从同版代码生成。JSONL 每行一个对象：

| 字段 | 类型 | 说明 |
|---|---|---|
| `record_id` / `book_id` / `run_id` | string | 当前记录、书籍和运行身份 |
| `name` | string | 原文已有名称，允许有证据的上下文补全；不能凭正文创造未命名概念 |
| `definition` | string 或 null | 可依据同书分散证据总结改写；null 表示缺乏足够释义，不应冒充完整知识点 |
| `aliases` | string[] | 有来源依据的别名；不主动翻译 |
| `category` | string | 语义分类名，不接入 S1–S5，不是枚举分类树节点 |
| `conditions` | string[] | 有证据的适用条件/范围，不能把推测或历史原因改成确定条件 |
| `evidence_ids` | string[] | 本书 units.json 中的来源 ID；回源按 run_id 隔离 |
| `candidate_ids` | string[] | 构成本记录的候选，用于名称审计与关联错误定位 |
| `scope` | string[] | 原文标题层级等上下文 |
| `issues` | string[] | 机器问题码与模型文字说明；保留交给下游，不能把非空 issues 一律理解为执行失败 |

字段示例见[中文实际记录](../../examples/records/chinese.json)和[英文实际记录](../../examples/records/english.json)，均取自最新zj `qwen3.8-max` 的 `md-v3.2` 实测，输入书籍来自120本书目，记录保留原始字段；来源位置见[样例出处](../../examples/provenance.json)。它们不是语义质检金标准。Schema 校验只能约束静态结构；真实来源归属、名称原文依据、分组分区等动态约束还需 Pydantic context 和运行验证器。

`units.json` 保存原文单元的 `id`、`text`、行范围、标题路径、类型等，单元文本按顺序可回拼 `source.md`。候选中的 `evidence_spans` 是相对对应 `Unit.text` 的 Python 字符半开区间 `[start,end)`，不是字节偏移或原始 PDF 页坐标。最终 Record 没有逐句释义跨度；经 candidate_ids 可追踪候选来源，不能宣称每句改写都获得逐字对齐。

## 5. 中间候选与名称审计

Candidate 不带生成释义。包含 candidate_id、chunk_id、name、scope、evidence_ids、name_evidence_ids、evidence_spans、origins、aliases、issues。`origins` 标记正文、目录、索引或词汇表来源；名称出现位置不自动等于释义依据。对应 `schemas/md-candidate-v2.schema.json`。

`name_decisions.jsonl` 记录每个候选的 accept/reject/uncertain/unreviewed、依据及组归属。明确 reject 不进入最终记录；uncertain 保留标记；unreviewed 是未完成工作。不要把候选数量直接当知识点数量或召回率。

## 6. 状态、退出码和失败处理

| 状态 | 接入处理 |
|---|---|
| `running` | 仍可能写盘，不可作为终态快照消费 |
| `complete` | 必要流程完成且无阻塞错误；仍可能有空释义和质量提示，必须经过下游清洗 |
| `partial` | 已保留部分结果，同时有发现/综合/复核等缺口；不能当全书成功 |
| `failed` / `interrupted` | 查看 fatal_error、batch 摘要和事件，可能没有完整产物 |
| `skipped` | CLI 明确跳过的语言；通常没有新的逐书运行目录，不算成功提取 |
| `not_started` | 批次致命失败后未执行的输入；通常只存在于 batch 摘要 |

某些异常会在进入完整 run 初始化前失败，应联合看调用异常、退出码和 batch，不假定每本都有 manifest。批次成功条件由上游定义为输入覆盖齐全且每本满足业务要求，不能只看进程结束、HTTP 200、校验脚本退出 0 或 records 文件存在。

## 7. 清洗交接与幂等

记录文件是**本 run 的完整快照**，不是仅追加的增量。恢复后可能新增、合并、改写记录；下游应按 `(book_id, run_id)` 接收并事务替换整份快照，或明确做差异核对，不能无条件追加。导入状态提交必须晚于文件读完和完整性检查。

若允许从 partial 书交付已完成记录，使用 `scripts/export_cleaning_delivery.py` 中的 `exclusion_reasons()` 同一口径：必须有非空释义；排除调用失败、未复核、上下文未完成、超预算及跨批分组延后的标记，并按 manifest 的 record_id/candidate_ids/chunk_id 排除关联错误。其余名称不确定、证据截断等质量说明仍保留供清洗；该筛选不是语义金标准。

可选导出按 `books/<book_id>/records.jsonl` 逐书输出，复制必要 units/manifest，附 books.json、summary.json、excluded.jsonl、checksums.json。导出记录增加 `provenance` 元数据；它不属于原始 Record Schema，下游严格校验 Record 时先分离该字段。空交付书只记索引，不产生空文件。输出目录是不可覆盖的固定快照。

## 8. 释义置信度与兼容边界

新生成的 Finding 必须提供 `confidence: high|medium|low`，由综合或复核模型评价提取忠实度，而非原文命题的确定性；具体疑义放在 issues。high会按稳定哈希抽检约10%，不能把任意high当作已通过额外复核，也不能把 low 当作 API 失败。Record 读取历史实例时允许字段缺失并呈现 null（未知），不会给旧结果补造模型评分。当前中英文示例已替换为新版实测输出，均实际包含confidence、support_reason和definition_supported；缺字段兼容仅针对历史数据读取。

本版提示协议为 md-v3.2，旧综合缓存不能直接恢复为新协议。当前生产模块清单明确参与实现指纹，CLI 和无关脚本不改变书内缓存身份；内容配置、提示及 Schema 校验仍保留。已移除旧局部释义复核和未启用主体提名实验，当前不产生 name_resolutions.jsonl。清洗导出器仍识别旧交付中的 quality_unverified，以免把历史未完成记录误交付。

新响应还必须包含 `support_reason` 与 `definition_supported`，顺序为依据、支持判定、释义。`false` 必须对应 `definition=null`、`conditions=[]`；`true` 必须有非空释义。原文明确的分类或关系可支持有限释义，名称提及、索引定位、致谢分工本身不能；缺失说明留在support_reason/issues。Record读取旧实例时这两字段可为null（未知），不回填虚假的模型判断。语言、引用及成员校验不因评分或来源判定而放宽。
