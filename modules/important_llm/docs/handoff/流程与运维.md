# 流程与运维

## 1. 当前执行流程

1. **输入和身份**：检查 MD、非空内容、可选 SHA256，计算配置指纹和 run_id，获取独占 `.running` 锁。源码/模型/输入身份不匹配时不能冒用旧检查点。
2. **结构解析和区域预处理**：markdown-it-py 建立保留原文的单元。规则先识别目录、索引、词汇表等候选区域；只有被路由且需要决策的区域交给 LLM 判断 retain/exclude/uncertain，不逐段额外调用 LLM。未列出的正文默认保留；不确定区域保守保留。规则候选在排除区域前提名。
3. **原生分词分块**：按结构边界和 4000-token 默认预算分块，保护正常尺寸表格/代码/公式；超大单元有界拆分并保留来源映射。Chonkie/原生计数用于当前 MD 路线，不要求 DoclingDocument。
4. **名称发现**：LLM 只识别原文已有名称和相关单元，程序回取原文证据；不在此阶段编写释义。有界邻文补取及失败拆块改善缺失上下文，不能无限向前后扩张。
5. **规则增强**：目录/索引/词汇表的名称提名，精确反查同书正文并收集证据。不会把所有标题直接当知识点；截断命中、表格等限制保留问题码，与正文发现共用候选池。
6. **逐书综合**：依据证据对候选做有界分组、名称 accept/reject/uncertain 判定，然后总结释义。单例也会经历名称检查。每条先写support_reason并判断definition_supported；只有有实质来源依据时才写释义，不足必须null且conditions=[]。校验器拒绝判定与输出矛盾的响应，不自动删字段掩盖错误。机械 ID 映射、原文取片、缓存和成员覆盖检查由代码完成。
7. **定向复核**：综合模型必填 high/medium/low 三级提取忠实度；非空释义的 medium/low 进入一次独立回源复核，high 按书籍及候选身份SHA256稳定抽检约10%。抽样比例集中在synthesis.py的HIGH_CONFIDENCE_SAMPLE_PERCENT；小样本不保证精确比例。旧交付记录若缺该字段按未知处理，不伪造评价。复核仍低置信度时保留该值，不循环求高分；空释义不强制补写。置信度是模型自评，不是校准概率或语义验收；抽检未覆盖的高置信度仍可能漏检。原文是猜想、可能性或只有范围有限的结论，不自动降低置信度：评价的是提取是否忠实保留这些限定。所有级别始终执行来源、成员、语言和格式硬校验。综合和复核在同一有界工作池中流水线推进，已生成记录无需等全书综合结束才复核。
8. **导出与记账**：逐书保存 records、名称审计、manifest、各阶段检查点和 execution 账本。调用方在终态后做结构验证、统计，再进入独立清洗。

`regions.json=[]` 可能正常，表示未路由任何特殊区域；它不是全文区域分类表。应结合 `preprocess_summary.json` 区分无候选、排除、uncertain 与执行失败。不能单看空数组判断预处理失效。

区域提名仅扫描首尾约 5% 非空单元：相邻中英文书目信号至少两类，或独立花括号对象文本。代码、表格、公式不以此规则提名。ISBN、CIP、Library of Congress、Cataloguing-in-Publication、Published/Printed by、Copyright 等只用于路由；转换器字段不再触发直接删除。模型必须依据上下文确认纯出版信息或转换元数据才可 exclude，正文示例、失败、超预算和不确定内容均保留。此稀疏路由不保证识别全部噪声。

## 2. 模块与依赖

| 文件/依赖 | 当前职责 |
|---|---|
| markdown.py / markdown-it-py / Chonkie | 原文单元与 MD 分块 |
| tokenization.py / Transformers / tokenizers | 本地原生分词与聊天模板计数 |
| models.py / Pydantic | 字段、来源、成员及语言约束 |
| llm.py / OpenAI SDK / Instructor / Tenacity | 结构化调用、共享请求队列、预算和有界重试 |
| prompts.py | 集中维护结构化提示，修改会影响缓存身份 |
| rule_candidates.py | 结构区域提名和同书证据反查 |
| pipeline.py | 单书各阶段编排、来源、缓存和状态 |
| synthesis.py | 书内分组、释义综合、定向复核 |
| telemetry.py | 事件账本和单执行统计 |
| storage.py | 标准库原子替换及 Windows 暂时共享锁有限重试，不是数据库 |
| cli.py | 单书/多书入口、服务选择、调度、恢复和 batch 摘要 |

LangExtract、Docling Graph、ExtractThinker、DSPy 等不是本版运行依赖。交付包不含历史比较实现；需要接入的只是当前模块。

## 3. 并发与预算

HTTP 槽位在同服务、同客户端的各书各阶段及重试间共享，按书轮转，同书内部 FIFO。退避和等待不占 HTTP 槽位。`--workers` 是每书逻辑工作数，`--max-connections` 是真实请求上限，不能相乘后理解为请求容量。预取只在请求不足时补位，最多驻留 book-workers + book-prefetch 本。

开始接入先用 1 书、4 请求；根据持续负载、排队、超时和有效产出调大。不能直接把某次生产使用的 96 并发当任意服务推荐值。超时后服务端计算可能仍继续，客户端释放槽位不代表 GPU 计算已经停止。基础架构反向代理也可能产生 504。

完整请求应用实际聊天模板后计数并预留输出。默认客户端 context_limit 为 32768，可在 Python API 显式调整；服务可能支持更大窗口，但必须同时评估输出预算和延迟。增大分块通常减少请求数，也会增加单次生成时间、成员遗漏和重试成本，不能只靠上限解决吞吐。

## 4. 重试与恢复

SDK 的隐式重试关闭，由统一调用层管理。普通逻辑调用默认最多 3 次；504 有独立额外额度，`gateway_retries` 默认 10；设置 transport_failure_limit=2 后，一次逻辑调用累计连接/5xx 故障达限会抛 DeferredCallError，使未完成工作保留为 partial，等待调用方安排后续有界补做。429 等可重试响应仍需考虑服务限流。

一次书级恢复会重建其快照并重新验证成功检查点，不意味着全书都重新付费。无进展或可重复的语义/结构错误不要反复整批恢复；先定位错误原因。跨批分组缺口可能来自确定性预算拆分，重试不会自动补全缺失的比较。

402 预算不足、401/403 鉴权及其他不可重试的 4xx 在发现、预处理、综合、复核和 CLI 共用致命错误判定，向上传播并取消批次新提交；408/409/429 保持有界重试。在途请求可能已到服务端，不能保证取消远端计算。修复预算或配置后再显式恢复，不自动重新启动整批。

同配置、同原文恢复使用 `--resume-existing`；完整书先离线验证后复用，partial 尝试未完成部分。源码指纹变更仅能在确认兼容、回归通过后显式加入白名单，不能放宽模型、提示或来源校验。改变模型/提示/温度/分词器应创建新运行，不复制旧模型内容缓存。

`.running` 防止同一 run 双写。正常退出会删除；强杀可能遗留。先核实锁内进程和主机确实已停止，再由运维清除对应单个锁。严禁删除活跃锁或自动递归清空结果目录。输出的 `.ready` 是已完整落盘的响应，恢复会验证后提升；`.tmp` 不能当成功缓存。

## 5. 统计和成本

每次执行写 `executions/<execution_id>/events.jsonl` 及 summary；恢复创建新 execution，不覆盖历史账本。manifest 中 execution_stats 仅是最新一次，历史总费用需汇总所有不同 execution/event 一次。不要把当前记录数与各次历史记录数相加。

verification_selected记录confidence与high_confidence_sample等选取原因，verification_result记录释义是否改写、是否置空及最终来源判定，便于量化抽检成本和纠正效果。请求事件区分 queued、started、finished、校验、cache_hit 与 deferred；可观察排队秒数、在途数、阶段耗时、HTTP 状态、重试耗时及实际 usage。`input_tokens` 是本地原生计数，`usage.prompt_tokens/completion_tokens` 是服务返回计费依据。缓存 token 是输入子集，reasoning 通常是输出子集，不能再次相加。

未返回 usage、开始但未结束的请求用量未知，不能记为零收费。`usage_is_complete` 只代表输入/输出量覆盖，缓存/思考细分仍需查 usage_missing。默认没有模型价格，pricing=null；下游按有效日期、币种和服务费率计价，不用估算单价冒充实际成本。

本地 cache_hit 不发 API；服务 cached_tokens 仍属于真实请求。成员校验、复核观察可能包含缓存重放，不可直接当本轮新请求数或错误率。父阶段耗时包含子阶段，work_seconds 不是墙钟耗时；并行时累计调用时间可远大于批次耗时。

事件不存正文、完整模型回答或 API 密钥；实际证据和结果文件含输入内容，交接权限由调用方管理。日志写入故障会中止执行，避免无账本地重复付费。

## 6. 当前能力边界

- 多本能成功运行不等于语义质量已经达标；独立知识点名称仍需下游清洗，不能保证完整召回。
- 同书多处证据能够汇集，但分组是有界的；超预算拆分、非词面同义、别名桥接和跨批分组仍有盲区，相关问题必须保留。
- 名称/别名必须有来源，语言需与来源一致；严格校验可能导致反复失败，不应为提升完成率删除这些检查。
- 原 MD 的 OCR、表格、公式损坏不会被本模块可靠修复；不读取图片内容。
- 模型的 uncertain 与 API 失败是不同状态；前者不应被自动无限重试。
- 服务模式、上下文大小、分词模板和模型质量需要接入方自行联调。本包不含推理服务部署器或实时监控守护进程。

本版保留 SDK 最终请求包装以精确计算含 Schema/纠错消息的 token；锁定依赖版本并由离线 HTTP 回归覆盖。重试历史压缩依据解析失败事件、原始消息前缀及角色结构，不依赖 Instructor 的英文错误句子。日志过滤仅作用于当前提取调用，不全局关闭第三方日志。

修改后先跑离线回归，再用目标服务验证小样本和真实书籍。Ruff 配置为 Python 3.12、88 列、4 空格、双引号、LF；不要压行。安装开发工具可执行 `python -m pip install ruff==0.16.8`，然后 `ruff check src scripts tests examples` 与 `ruff format --check src scripts tests examples`。
