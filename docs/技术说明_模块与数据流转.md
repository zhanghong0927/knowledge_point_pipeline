# 技术说明：模块与数据流转

现行约定：2026-10-15。历史说明已移至`history/`，当前入口及安装见[项目README](../README.md)。

## 数据流

```text
原始书目 → 筛选及MD质量/结构分类
  ├─ 辞海：entry_prose准入 → 完整MD模型抽取 → 原文核验 → 辞海原生清洗
  └─ 重要书籍：N1/N3准入 → 规则或独立LLM抽取 → 通用规则及模型清洗
        ↓ 两路分别生成通过项和交接证明
  正式清洗导出：保守名称空白修正、原名追踪
        ↓ 同学科可合流
  固定项目树/边界导入 → 分类匹配 → 可选挂载复核（默认关闭）
        ↓ 仅合格路径导出
  同完整路径名称/空白变体去重 → 保留、移除及验证报告
```

## 模块职责

| 范围 | 主要入口 | 责任 |
|---|---|---|
| 总调度 | `pipeline.py` | 单配置计划、检查、任务状态、同身份接续 |
| 分轮调度 | `staged_benchmark.py`、`stage_scheduling.py` | 阶段分离、整批三轮、阶段额度及目标数量 |
| 全局请求 | `adapters/inference_gateway.py`、`shared_request_pool.py` | 共享HTTP与生产者预算，暂停/排空/切换，不按单书固定分配 |
| 抽取与清洗 | `modules/dictionary/`、`modules/important_books/`、`modules/cleaning/` | 两路原生处理与证据校验 |
| 清洗交接 | `adapters/dictionary_cleaning.py`、`adapters/normalize_records.py`、`adapters/cleaning_handoff.py` | 通过项导出、来源恢复、指纹证明、名称规范化 |
| 项目分类资产 | `project_taxonomy.py`、`project_assets/LOCK.json` | 同一发布版本的树与边界导入、完整性检查 |
| 挂载 | `adapters/mounting_bridge.py` | prepare、分类匹配、可选复核及标准导出 |
| 去重 | `modules/dedup/` | 同路径比较，保留原始记录并核对守恒 |
| 轮次完整性 | `round_integrity.py` | 控制器内复用哈希，变化/重启/最终化完整校验 |

## 字段与交接

标准记录包含`id`、`name`、`knowledge_point`、`definition`、`en_definition`、`description`、`en_description`、`source`、`tag`、`main_tags`、`related_tags`。定义和描述分别保存，均可为空；原始正文或上下文不能直接当成已确认定义。

来源通过初次标准化、原生清洗回执及trace绑定。辞海必须核对原MD哈希、原文位置和书目身份；重要书籍恢复来源也必须匹配原始记录，不为来源替换重新签发通过证明。

正式清洗出口只导出原生通过项。名称空白修正仅处理名称字段，有原名或已核查规则支持时才拼接中文拆字；保留正常英文词界、数字单位、型号与公式空格。原始名称、命中规则和疑似问题写入trace；原生检查点不被改写。

挂载只更新合法路径及必要学科标签，不补造定义、描述或来源。去重比较键可以归一化空白，保留/移除记录的原始payload不改写。

## 状态口径

| 状态 | 含义 |
|---|---|
| 抽取partial | 已验证子集可按显式配置交接，未解决项另存 |
| 清洗未接受/待定 | 内容、名称或学科判断未通过或证据不足，不混作接口故障 |
| 挂载导出 | 接受的候选路径通过层级、得分和树链校验；启用复核时还需满足复核要求 |
| 分类不确定 | 模型返回needs_review，或候选路径未满足深度、分数、树链等接受条件 |
| 未接受 | 模型给出out_of_scope、insufficient_evidence等未接受结论 |
| 技术失败 | 接口、JSON或结构等技术处理失败；摘要区分传输、格式及其他类型 |
| finished_with_unresolved | 技术流程已收尾，但仍有未解决范围 |

分类不确定是结果状态，不意味着正在执行复核。挂载复核关闭时也不自动放行。不确定与未接受可能存在语义重叠，以原生回执为准。

## 调度、重试和完整性

批量入口按阶段运行整批首轮与两轮重试；额度为各阶段首轮上限、其1/4和1/16，最小为1。16卡参考可显式配置512 → 128 → 32，但不等于实测最优。单配置入口的任务级resume不能替代全局分轮恢复。

成功子请求复用；可重试传输失败及已识别挂载格式异常进入后续轮次，有效语义结论不重试。正文修复批次最多8项，输入超长或回复截断时缩小批量，保留原文及修复身份约束。

同控制器内复用未变化文件的哈希索引；目录仍枚举，变化与事件篡改仍检查，重启和最终化仍完整读取。源码、服务、输入及分类资产身份变化需要显式迁移，不能仅修改SHA绕过旧检查点。

技术验证不等于语义验收。重要书籍名称型抽取、OCR误字、证据不足及当前40个空边界节点等限制仍需保留。
