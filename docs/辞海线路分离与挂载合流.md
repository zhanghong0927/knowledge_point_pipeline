# 辞海线路分离与挂载合流

现行约定：2026-10-15。两类独立抽取和清洗；同学科挂载共用项目固定树与边界，知识点挂载复核默认关闭。

## 准入与抽取

辞海默认`dictionary_approval.allowed_families: ["entry_prose"]`，须同时满足MD、结构与原文证据校验。重要书籍只处理N1/N3，规则抽取与独立LLM分支分别配置；N2/N4/N5不自动转入其他路线。

`dictionary_extraction.allow_partial`默认false。显式启用后也只交接原文核验通过的子集，未解决与结构风险继续隔离；不把缺字段或技术失败当空结果。

## 独立清洗

| 路线 | 原生处理 | 正式通过项 |
|---|---|---|
| 辞海 | 名称格式 → 学科范围 → 正文/定义选择及对应检查 | `04_cleaning/export/records.jsonl` |
| 重要书籍 | 初次标准化 → 规则清洗 → 模型判断 → 来源恢复 | `04_cleaning/export/records.jsonl` |

辞海原生`FINAL_RECORDS`、`DISPOSITIONS`、`REVIEW`、`TECHNICAL_FAILURES`和`STATE`保留。导出需核验清洗通过证明、原MD及位置证据；重要书籍来源恢复需匹配初次标准化记录、trace和原生keep结果。

两类正式出口都执行保守名称空白修正，保留原名和规则记录；定义、描述、ID与原文不因此补写。原生中间结果和旧导出不被自动升级。

## 同学科合流

先分别取得两路已通过的清洗导出，再在新配置、新运行目录中指定多个输入：

```json
"mounting": {
  "inputs": [
    "/absolute/dictionary/04_cleaning/export/records.jsonl",
    "/absolute/important/04_cleaning/export/records.jsonl"
  ],
  "review_enabled": false,
  "threshold": 0.85,
  "min_depth": 2,
  "max_depth": 5,
  "max_related": 2,
  "workers": 16,
  "boundaries": {"source": "project", "enabled": true}
}
```

```bash
python -B pipeline.py plan --config configs/join.local.json --stages 05,06
python -B pipeline.py check --config configs/join.local.json --stages 05,06
python -B pipeline.py run --config configs/join.local.json --stages 05,06
```

配置仍需完整的学科、模型及路径字段；示例片段不能单独替代配置文件。输入必须属于同一学科并带有效清洗证明，混合学科、来源串换及身份不匹配不会自动放行。

## 固定资产与导出

两路使用`project_assets/LOCK.json`指定的同一版本。正常入口导入固定树、边界与原生证明，不再按任务生成。当前未发布学科会拒绝执行；维护与发布新资产须单独进行。

`mounting.review_enabled=false`时：分类匹配 → 标准导出 → 长度去重及验证。设为true才执行原知识点路径模型复核，不改变分类边界自身的原审查状态。

挂载导出仍核对得分、深度和树链。不确定、未接受、技术失败独立输出；新代码不自动重放旧失败或修改历史结果。去重按同完整主路径比较，空白变体仅使用已核查规则归并。
